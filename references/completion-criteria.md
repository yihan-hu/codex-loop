# Completion Criteria

Final semantic acceptance is model work, not a receipt protocol.

Before finishing a substantial task:

- Re-read the user's effective request, including later corrections.
- Inspect the actual current artifact/diff/state.
- Confirm every material requested outcome is present.
- Run the smallest still-needed relevant validation on the current state.
- Preserve unrelated user work and avoid incidental changes.
- Reconcile consequential external actions and task-owned processes.
- State any real unresolved limitation.

Use one additional Codex-style review only when change size, uncertainty, test weakness, or risk justifies it. A repair should trigger targeted revalidation, not a default full checker replay.

`completion` checks deterministic blockers only. It does **not** require per-criterion PASS evidence, steer acknowledgements, repeated fresh reviewer PASSes, or a separate requirement-by-requirement objective audit.

For high-impact operations, domain-specific Skills and host safety/approval requirements remain authoritative and may add stricter completion conditions.
